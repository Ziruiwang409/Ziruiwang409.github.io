D41: observed-cell preservation (A vs B) on ScanNet++

Stage 1 = Complete3D-v2 (100k) or a D41 arm (SAGE-only, GenRecon init + layout recipe, 20k EMA); stages 2 and 3 stock · inputs 8 DSLR views + VGGT-Omega points from those views (+ oracle layout boxes where marked) · paired n = 136 (3D), 136 (2D) · 2026-10-19 · companion pages: image-only benchmark · v2 (VGGT) · v2 vs stage-2 run 1

Two SAGE-only stage-1 fine-tunes from the released GenRecon model with the D36 layout recipe (20k steps): A trains with plain flow matching, B adds a term that keeps the cells the input observed (occupied or carved free). Same inputs as v2 (8 DSLR views + VGGT points; + layout = the oracle room boxes), stock stages 2 and 3. B + layout is the best 3D result: CD 0.0601 → 0.0566, F@10 0.840 → 0.849, better than v2 in 87/136 scenes; B without layout ties v2 in 3D (0.0604, 72/136). B's gain over A is higher observed precision (2 cm: 0.237 → 0.251 with layout) and fewer false positives in space the input never saw; surface in carved-free cells is unchanged. The 2D renders do not follow: B's normals and LPIPS are worse than A's (normal° 22.23 → 22.88, LPIPS 0.480 → 0.488 with layout), and A + layout keeps the best 2D row. In the gallery, the two largest gains are rooms where v2 leaves space empty and surface floating outside the room (e3b3b0d0c7, e050c15a8d); both layout runs fill them, and B without layout leaves more floating pieces than either. Filling is not always right: in e050c15a8d's held-out frames every D41 run puts a wall slab across the middle of the view. In the typical and loss scenes the four runs look alike at this scale; in defd3457db all four over-fill the lower half of the room relative to the GT.
